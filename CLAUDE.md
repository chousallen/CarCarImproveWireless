# CarCarImprove

## ESP32 firmware (`esp32-hm10/`)
- Built with ESP-IDF v6.1 at `/media/sallen/SSD-Programs/esp/v6.1/esp-idf`
  (tools: `IDF_TOOLS_PATH=/media/sallen/SSD-Programs/esp/.espressif`; `get_idf` in `~/.bashrc` loads it).
  The source tree was copied from sallenpi `~/esp/esp-idf` (clean v6.1 git checkout); sallenpi's own
  tools are aarch64 and must not be copied. v5.5.2 is still installed next to it.
- Build/flash: `get_idf; cd esp32-hm10; idf.py set-target esp32; idf.py build; idf.py -p /dev/ttyUSBx flash`.
  The code also builds on IDF 5.3+ (`esp_driver_uart` component exists since 5.3).
- IDF 6.x: the legacy `driver` component no longer pulls in `esp_driver_uart`; name it in `PRIV_REQUIRES`.
  Warnings are errors by default; the v6.1 build has zero warnings — keep it that way.
- `sdkconfig` is tracked (generated by v6.1 from `sdkconfig.defaults`). Put any lasting setting in
  `sdkconfig.defaults`, then regenerate. `sdkconfig.old` is not tracked.
- Two CH340 USB-serial adapters (ESP32 and the Arduino with the HM-10) take `/dev/ttyUSB0`/`1`
  in plug order. Identify the ESP32 with
  `python -m esptool -p /dev/ttyUSBx chip-id` (from the IDF python env) before flashing.
  `chat_hm10/chat_hm10-esp32.py` hard-codes `PORT = '/dev/ttyUSB1'`.
- `idf.py monitor` needs a TTY. From a non-interactive shell, read the port with pyserial
  (115200 baud; pulse RTS to reset).
- UART commands are handled on the ESP32, not forwarded to the HM-10: `AT+NAME?`, `AT+NAME<name>`
  (saves the target name to NVS, no reboot), `AT+STATUS?`, `AT+RESET`. Received BLE data is logged with
  tag `bt_com`; successful writes log nothing (only failures do). HM-10 MTU is 23, so data goes out in
  chunks of 10 bytes.
- `OK+CONN` means notifications are enabled (`link_ready`), about 0.8 s after the scan finds the HM-10.
  The `connect` flag is set earlier, at scan time, and only stops a second open. UART data sent before
  `link_ready` is dropped with a `link not ready` warning. Reconnect after `AT+RESET` takes about 6.3 s.
- The bench Arduino Mega runs a plain pass-through (USB `Serial` at 115200 ↔ `Serial3`/HM-10), not
  `init_hm10.ino`: it prints no banner, and opening its port does not reset the HM-10.
- Hardware test: `python tests/hw_e2e.py --esp /dev/ttyUSB0 --mega /dev/ttyUSB1` (conda env `carcar`,
  ~2 min, 22 checks, exit 0 = pass). See `tests/README.md` for the bench setup.
